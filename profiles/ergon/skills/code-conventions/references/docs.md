# Docs

Every repo gets a docs site on **Read the Docs**, autogenerated from
docstrings. Target state: all repos, not just the ones that already have it.

## Stack

- **MkDocs** with the **Material** theme.
- **mkdocstrings-python** renders the API reference directly from
  docstrings — **Google format** (see `toolchain.md`). The docstring is the
  single source; nothing about the API is duplicated into markdown by hand.
- **Read the Docs** builds on every push to the default branch, configured
  by `.readthedocs.yaml` (template: `templates/readthedocs.yaml`). No docs
  workflow in GitHub Actions — RTD is the builder.

## Layout

```
mkdocs.yml            # site config (template)
.readthedocs.yaml     # RTD build config (template)
docs/
├── index.md          # landing: what it is, install, quickstart
├── usage/            # narrative docs, written by hand, thin
└── reference/        # mkdocstrings entry points, one page per public module
```

## Rules

- **Narrative docs are thin.** Installation, quickstart, the handful of
  things a docstring cannot say. The substance lives in docstrings; if a
  narrative page starts re-explaining an API, the docstring is what needs
  the work.
- Reference pages use mkdocstrings directives (`::: package.module`) — one
  directive per page, no copied signatures.
- Docstring examples must be real, runnable usage. A wrong example in a
  docstring is a bug in the package, not in the docs.
- README is not docs: badge, one-paragraph description, install line, link
  to the RTD site.
